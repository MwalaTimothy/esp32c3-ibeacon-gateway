This is a binary-only release repository: no firmware source code is
included. Flashing uses the pre-built merged binary in this repo with
esptool.py. See README.md for the full reference documentation.

 SECTION 1: HARDWARE SETUP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

REQUIRED COMPONENTS
───────────────────
 - ESP32-C3 microcontroller (LOLIN C3 Mini recommended)
 - 12x addressable RGB LED ring (NeoPixel-compatible)
 - USB-C cable (power + serial data)
 - Computer running Windows 10+, macOS, or Linux
 - WiFi network with internet access (2.4 GHz)
 - Backend/KDS server on your network (IP:port)

 SECTION 2: FIRMWARE FLASHING (pre-built binary)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP A: Install esptool
  - Open a terminal / command prompt
  - Run: pip install esptool

STEP B: Find your serial port
  Windows:
    - Device Manager -> Ports (COM & LPT)
    - Look for "USB Serial" or "CH340"/"CP210x"
    - Note the COM port (e.g., COM3)

  Mac:
    - Terminal: ls /dev/tty.*
    - Look for /dev/tty.usbserial or /dev/tty.SLAB*

  Linux:
    - Terminal: ls /dev/ttyUSB*
    - Look for /dev/ttyUSB0

STEP C: Flash the merged binary
  Windows:
    esptool.py --chip esp32c3 --port COM3 --baud 460800 ^
      write_flash -z 0x0 esp32c3-ibeacon-gateway-v2.2.0.bin

  Mac/Linux:
    esptool.py --chip esp32c3 --port /dev/ttyUSB0 --baud 460800 \
      write_flash -z 0x0 esp32c3-ibeacon-gateway-v2.2.0.bin

  This single file already contains the bootloader, partition table, and
  application - one command, one offset (0x0), done.

EXPECTED OUTPUT:
  - esptool.py v4.x
  - Connecting...
  - Chip is ESP32-C3 (revision: 1)
  - Writing...
  - Hard resetting via RTS pin
  - Done!

 SECTION 3: OPENING A SERIAL MONITOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Arduino IDE (Windows/Mac/Linux)
────────────────────────────────
  - Tools -> Serial Monitor
  - Bottom-right: Check baud rate = 115200
  - Press reset button on ESP32-C3
  - You should see boot messages

PuTTY / Tera Term (Windows)
────────────────────────────
  - Download: https://www.putty.org/
  - Serial line: COM3 (your port)
  - Speed: 115200
  - Connect

Terminal (Mac/Linux)
─────────────────────
  - screen /dev/ttyUSB0 115200
  - Press reset button on ESP32-C3
  - To exit: Ctrl+A, then Ctrl+D

  OR:
  - picocom /dev/ttyUSB0 -b 115200
  - Ctrl+A, Ctrl+X to exit

 SECTION 4: INITIAL CONFIGURATION (180-Second Window)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

You have 180 seconds (3 minutes) after boot to configure the gateway.
After 180 seconds, the configuration window closes automatically.

The RGB ring breathes blue with rainbow accents during this window.


STEP 1: View Current Configuration
──────────────────────────────────
Type in serial monitor:
  CONFIG

You will see:
  ========== GATEWAY CONFIGURATION ==========
  Firmware Version:  2.2.0
  Gateway ID:        gateway-001
  Beacon UUID:       8a46676d-6348-4d50-a0e6-af5a508def40
  Target Major:      1
  KDS Server:        192.168.1.100:8080
  Scan Interval:     5000 ms
  Report Interval:   10000 ms
  WiFi SSID:         <not set>
  WiFi Password:     <not set>
  WiFi Status:       Disconnected
  Tracked Beacons:   0
  ===========================================


STEP 2: Configure WiFi
──────────────────────
FASTEST METHOD: One-liner setup + connect + save
Type:
  AT+WIFI=YourSSIDName,YourPassword

Example:
  AT+WIFI=Office,SecurePass123

The connection happens in the background - wait a few seconds, then type
WIFI STATUS to confirm:
  [INFO] WiFi connected successfully
  [INFO] IP Address: 192.168.1.50
  [INFO] RSSI: -45 dBm

ALTERNATIVE METHOD: Three commands
Type:
  SET WIFI_SSID Office
  SET WIFI_PASS SecurePass123
  WIFI CONNECT


STEP 3: Verify WiFi Connection
───────────────────────────────
Type:
  WIFI STATUS

You should see:
  WiFi is connected
  SSID: Office
  IP: 192.168.1.50
  RSSI: -45 dBm


STEP 4: Configure Backend/KDS Server
─────────────────────────────────────
If your backend server is NOT at 192.168.1.100:8080, update it:

Type:
  SET KDS_IP 192.168.1.100
  SET KDS_PORT 8080

(Replace with your actual server IP and port)


STEP 5: (Optional) Configure Gateway Identity
────────────────────────────────────────────────
If you want to change the gateway ID (default: "gateway-001"):

Type:
  SET GW_ID kitchen-1


STEP 6: Save Configuration
──────────────────────────
Type:
  SAVE

You will see:
  [INFO] Configuration saved to NVRAM

All settings are now persistent (survive power cycles and firmware updates).


STEP 7: Wait for Automatic Exit
───────────────────────────────
After 180 seconds, you will see:
  [INFO] Configuration window closed
  [INFO] WiFi is connected - Beacon data will be sent to KDS
  [INFO] Gateway is now running. Listening for beacons...

The gateway is now in operational mode.

 SECTION 5: TESTING & VERIFICATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1: Confirm the Gateway is Listening
─────────────────────────────────────────
In the serial monitor, you should see:
  [INFO] Starting continuous BLE scan for beacons with Major: 1
  [INFO] WiFi is connected - Beacon data will be sent to KDS
  [INFO] Gateway is now running. Listening for beacons...


STEP 2: Trigger a Beacon Near the Gateway
──────────────────────────────────────────
If you have a companion beacon device:
  - Power it on (or activate it)
  - Bring it within a few meters of the gateway

The gateway should detect it within a few seconds. The ring flashes white
briefly on first detection, then settles to a green breathing pattern while
the beacon stays in range.


STEP 3: Monitor Serial Output
─────────────────────────────
You should see a beacon detection log line, and can type BEACONS at any
time to list everything currently tracked (RSSI, seen-count, uptime).

If you have a generic BLE scanner app (e.g. nRF Connect) you can also
verify the beacon is advertising the expected UUID independently of the
gateway.


STEP 4: Verify Reporting to Your Backend
──────────────────────────────────────────
Watch serial output for a "Sending beacon data..." line followed by a
success/failure result. On your backend server, check logs for POST
requests to the /beacons endpoint with a JSON body — see README.md for the
exact payload format.

If you see HTTP errors in serial output, check:
  1. Backend server IP/port is correct: CONFIG
  2. Backend server is running and reachable
  3. Firewall allows the configured port

 SECTION 6: TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

See the Troubleshooting section of README.md for the full reference. Quick
pointers:

  - Garbled serial text -> wrong baud rate; use 115200
  - Can't find the COM port -> install CH340/CP210x USB driver, restart
  - Flashing fails with a permission error -> try another USB port/cable,
    or (Linux/Mac) check you have permission to access the serial device
  - WiFi won't connect -> confirm 2.4 GHz network, exact SSID spelling
  - Beacons not detected -> BLE DEBUG ON, check UUID/Major match, move
    the beacon closer
  - Unexpected reboot -> check the reset-reason line in the boot log
